# Core is organised by domain and owns the Effect seams

> The source paths changed with [ADR-0007](./0007-default-bulletproof-source-layout.md). Domain ownership and Effect service design remain in effect.

`packages/core` is organised by domain (`auth/`, `cdn/`, `http/`, `i18n/`, `persistence/`, `session/`), not by kind (`apis/`, `services/`, `libs/`). Core owns the Session and the stored client state of every app, behind one seam: a `KeyValueStore` layer. Each app keeps only its platform adapters and its one runtime, in `src/core/layers/`. TanStack Query stays the owner of server state.

> Recorded on 2026-11-03, after commit `60f553711` moved both apps to Effect. The move made `Http` and the endpoints real Effect code, but the code around them stayed copied in each app.

## Vocabulary

> **Domain folder** — one folder per domain in core. An API domain has three files: `schemas.ts` (declarations only), `api.ts` (the endpoint Effects), and `queries.ts` (the query keys and the query and mutation option factories). An app feature that owns its own endpoints uses the same layout (`apps/expo/src/user/`).
>
> **Composition root** — `apps/*/src/core/layers/`. It holds the platform adapters (storage, transport, telemetry), the env `ConfigProvider`, and `runtime.ts`, which states the services that every app Effect can use.
>
> **Toolbox** — `hooks/`, `utils/`, `constants/` and `types/` in core. Plain code for apps that do not exist yet. It is kept even without a caller, and it is not rewritten on Effect: Effect gives value where there are effects, errors and dependencies, not in pure helpers.

## What core owns

**Persistence.** `makePersistence(kvsLayer, { defaultLocale })` returns the one atom registry, the atom runtime, and the Session, theme and Locale atoms. Each app calls it once, with `localStorage` (spa) or MMKV (expo). Tests call it with `KeyValueStore.layerMemory`. Every `Atom.kvs` key comes from `persistenceKeys` (or `featureFlagStoreName` in spa) and has a version suffix (for example `app-user.v1`), enforced by the `persistence/versioned-kvs-key` oxlint rule. A schema change of a stored value needs either a new key version and a migration from the old version, or a schema that decodes both shapes; otherwise `Atom.kvs` falls back to its default and drops stored data with no error. Committed snapshots of each stored shape are decoded by unit tests.

**The Session.** `Session` is a `Context.Service` with `accessToken`, `start` and `end`. `Http` gets it from its Layers. Before, `Http` took two callbacks (`getToken`, `onUnauthorized`), which the Layer graph could not see, and each app had its own End Session. Now there is one End Session flow, as the glossary says. The app gives only its extra step (`onEnd`: clear the query cache). `Session.layerMemory` is the second adapter at the same seam, so a test needs no module mocks.

**Query and mutation options.** Each factory takes any `ManagedRuntime` that provides the services it needs. `ManagedRuntime` is contravariant in its services, so a runtime that provides more is accepted. The app hook keeps only its own part (the toast).

**Retries.** Retry load needs a budget, so one layer owns the retries. TanStack Query is the retry owner for failed requests. `Http` does not retry, with one exception: after a 401, it refreshes the Session once. If the refresh gives a new Access Token, `Http` replays the request one time. Every `new QueryClient(...)` must set `defaultOptions.queries.retry` and `defaultOptions.mutations.retry`. The `tanstack-query/explicit-retry` oxlint rule enforces this. Thus the retry policy is a decision and not a library default. The app clients retry a query 3 times. They do not retry a mutation, because a mutation is not always safe to send again. The query retry does not yet skip errors that are not transient (for example a 404). Thus one query can send a maximum of 4 attempts. Each attempt can add one refresh call and one replay, so the total is a maximum of 8 requests and 4 refresh calls. Test clients set `retry: false`, so that a failure shows immediately. A test that proves a retry policy (for example, that a not-idempotent mutation is sent one time, ADR-0012) uses its own client that retries. Each mutation option factory declares its own retry safety (ADR-0012).

**Offline mutations.** Recorded on 2026-11-26 (issue #225). A mutation does not pause while the device is offline. It fails at once, and the UI shows the failure. With the default network mode (`"online"`), TanStack Query pauses an offline mutation and keeps it only in memory. A reload loses it, and the app does not tell the person. Thus every `new QueryClient(...)` sets `defaultOptions.mutations.networkMode: "always"`. The `tanstack-query/mutations-fail-offline` oxlint rule enforces this for inline options, and `tanstack-query/explicit-retry` rejects options that are not inline. An offline request fails with a `TransportError`, which `toFailure` shows as `errorNetwork` (ADR-0014). The person sees that the action did not occur, and can send it again when the device is online. Queries keep `networkMode: "offlineFirst"`: a lost query has no effect on the server, and the next mount fetches it again. The Route Test `login.e2e.test.tsx` sets the device offline and proves that a login fails with the network message, and that no Session starts. Expo does not yet connect `onlineManager` to the device network state, so TanStack Query in expo always sees the device as online. The expo setting makes sure that a later connection does not start to pause mutations.

## What each app owns

`src/core/layers/` only. Env goes through Effect `Config`: the layers read `EnvConfig`, the runtime installs one `ConfigProvider` over the env object that the bundler inlines, and code outside Effect reads its few values from `env`, from the same object and with the same rule. At startup, `env.ts` validates the whole `EnvConfig` one time with `allEnvVars` from `@workspace/core/config/env-var`. `allEnvVars` uses `Config.all`, collects the rejection of each variable, and gives one error that names every bad variable. Thus a developer sees all bad values in one run, not one value for each run. `readEnv` runs a `Config` against the env `ConfigProvider` and is allowed only in `lib/layers/` files. The `effect-config/no-scattered-read-env` oxlint rule enforces this, because a read outside the startup check stops at its one variable. The type of `AppLayer` in `runtime.ts` names the services the runtime must provide (`Http`, `HttpClient`, `Session`). `Layer` is contravariant in its output, so the build fails if one of them goes missing. This check exists because expo once hid `HttpClient` with `Layer.provide`, and `cdnApi` could not run there.

## Considered Options

- **Keep folders by kind and add `services/session.ts` and `atoms/`** — rejected. Folders by kind give each Effect concept no fixed location, and "everything about auth" was in three places.
- **Core atoms at module level, with the storage added by `Atom.context().addGlobalLayer` at startup** — rejected. `Atom.kvs` needs a runtime whose type includes `KeyValueStore`, so this needs a type cast, a hidden mutable global, and a startup order that must be correct. The `makePersistence` factory keeps the types correct and is the test surface.
- **A `QueryClient` service in core, so End Session clears the cache itself** — rejected. It couples the Session to TanStack Query. The `onEnd` step is a smaller interface.
- **Sync Session helpers (`get`, `set`, `end`) beside the Effect service** — rejected. Two write paths let a write skip `onEnd`. Writes go through the Effect; reads use `sessionAtom`.
- **Replace TanStack Query with `AtomRuntime.fn` / `runtime.atom`** — rejected for now. It would make one state system, but it rewrites every hook in both apps and removes the TanStack devtools and cache invalidation. Reopen it only with a new reason, not because "Effect everywhere" sounds cleaner.
- **One `AuthApi` / `CdnApi` `Context.Service` for each domain** — rejected. `Http` is already the seam, and MSW fakes the network under it (ADR-0002). A service with one adapter is a hypothetical seam.
- **Keep the Translation Provider in each app** — kept, as the glossary says. Only the Locale value moved to Persistence.
- **Persist paused mutations** (`persistQueryClient` with `setMutationDefaults`) — rejected (issue #225). The login variables contain the password, so the storage would keep it. After a reload, the app would send a not-idempotent login (ADR-0012) that the person possibly does not want any more. Reopen this only for a mutation that is idempotent and holds no private data.
- **Pause offline mutations in memory, and show a notice that a reload loses them** — rejected (issue #225). It adds a UI state to each app, and the work is still lost. A failure that the person sees is the smaller interface.
